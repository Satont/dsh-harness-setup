# dsh-workspace-profiles

Профили рабочих пространств для сайдбара DSH — как воркспейсы Zen: внизу сайдбара
переключатель, и в списке Workspaces остаются только рабочие пространства
выбранного профиля.

## Что делает

- Внизу сайдбара, над настройками, появляется полоса профилей (цветная точка +
  имя). Клик переключает профиль мгновенно. Слева от полосы — иконка-сетка
  «Все» без текста: возвращает полный список и подсвечена, когда фильтр
  выключен. Второй способ — повторный клик по активному профилю. Справа —
  плюс: настройка профилей. Если профилей ещё нет — по центру кнопка
  «Профили».
- Активный профиль фильтрует секцию Workspaces: строки рабочих пространств вне
  профиля и их сессии скрываются. Всё остальное поведение списка (группы,
  раскрытие, drag, меню, статусы) остаётся родным — плагин не заменяет браузер
  Workspaces, а только скрывает лишние строки.
- Плюс открывает настройку: профили, порядок, цвет, имя и галочки рабочих
  пространств, которые каждый профиль показывает. В свёрнутом сайдбаре (рейл)
  вместо полосы — одна кнопка с меню профилей; в меню остаётся пункт «Все»,
  а в настройке — ссылка «Показать все».
- Профиль без отмеченных рабочих пространств ничего не фильтрует — видны все.
  Такой профиль помечен на полосе полой точкой и подписью в подсказке.
- Новое рабочее пространство, добавленное при активном профиле, автоматически
  попадает в этот профиль.
- Пути удалённых рабочих пространств вычищаются из профилей автоматически, чтобы
  удаление в реестре не оставляло пустой сайдбар.
- Настройки хранятся на хосте в `$DSH_HOME/workspace-profiles.json`
  (по умолчанию `~/.dsh/workspace-profiles.json`) и переживают перезапуск,
  смену браузера и чистку localStorage. Реестр рабочих пространств
  (`~/.dsh/storages/workspace.json`), сессии и `cordis.patch.yml` не трогаются.

## Установка

Распакуйте архив в любую постоянную папку (не во временную) и ставьте плагин
из неё — это каталог, где лежит `package.json`.

Через веб-интерфейс: **Plugins → Add plugin**, укажите абсолютный путь к этой
папке, затем **Enable now**.

Через CLI:

```sh
dsh plugin --profile <профиль> add link:/абсолютный/путь/к/dsh-workspace-profiles
```

После установки клиентская часть подхватывается по **Ctrl+R**. Если правили
host-часть (`index.js`) — нужен полный перезапуск приложения.

## Настройка

1. Нажмите плюс справа от полосы профилей.
2. **Новый профиль** — создаёт профиль; имя правится прямо в строке. Новый
   профиль не активируется сам: сначала отметьте его рабочие пространства.
3. В правой колонке отметьте рабочие пространства, которые профиль показывает;
   подпись «в профиле X» показывает, что путь уже занят другим профилем (один
   и тот же путь может входить в несколько профилей).
4. **Показать этот профиль** делает профиль активным (то же, что клик по чипу).
5. Удаление профиля — корзина, затем подтверждение отдельной строкой под ним.
6. Изменения сохраняются сами, через 250 мс после последней правки; при
   скрытии окна черновик дописывается сразу. Ссылка «Показать все» внизу
   настройки снимает фильтр, не закрывая окно.

Файл настроек можно править и руками (при закрытом окне настроек):

```json
{
  "version": 1,
  "activeProfileId": "work",
  "profiles": [
    { "id": "work", "name": "Работа", "color": 1, "paths": ["/home/user/projects/work"] },
    { "id": "dsh", "name": "DSH", "color": 4, "paths": ["/home/user/work/dsh-workspace"] }
  ]
}
```

- `paths` — точные абсолютные пути зарегистрированных рабочих пространств (как
  в `workspace.json`), а не glob-шаблоны. Пути, которых нет в реестре, клиент
  вычищает при следующем изменении.
- `color` — индекс палитры 0–5.
- `activeProfileId: null` или отсутствующий профиль = режим «Все».
- Схема проверяется на хосте: id профиля — `[A-Za-z0-9_-]{1,64}`, имя 1–48
  символов, до 24 профилей и до 200 путей в каждом.

## Как устроено

Клиентская половина регистрируется в слоты `sidebar.footer.action` (полоса) и
`shell.overlay` (диалог), читает снапшот рабочих пространств через сервис
`workspaces` и держит один `<style>`, который прячет строки по штатным атрибутам
браузера Workspaces: `[data-sidebar-list-area] [data-row-key="workspace:<id>"]`,
`[data-row-key="session:<id>"]`, `[data-row-key="overflow:<id>"]`.
Диалог — нативный `<dialog>` с `showModal()`, поэтому он открывается поверх любых
панелей и маски drawer-режима.

Host-половина отдаёт `GET/PUT /workspace-profiles/config` и пишет JSON
атомарно (уникальный временный файл + rename, записи сериализованы), с
валидацией размера тела, `Content-Type: application/json`, схемы и путей.

## Ограничения (честно)

- Это фильтр отображения, а не удаление: скрытые рабочие пространства остаются
  в реестре, их сессии доступны через поиск, а hero-пикер рабочего пространства
  (для новой сессии) не фильтруется — там видны все.
- Поиск в сайдбаре по-прежнему находит сессии из скрытых рабочих пространств;
  открытие такой сессии не показывает её строку, пока профиль не переключён.
- **Новая сессия**: если «Новая сессия» попадает в рабочее пространство, которое
  активный профиль скрывает, строки в сайдбаре не будет. Снимите фильтр
  или добавьте это пространство в профиль.
- Сессии без рабочего пространства (Ungrouped) видны при любом профиле.
- Режим **Workspace Tree**: если родительское рабочее пространство скрыто, а
  дочернее входит в профиль, дочерняя строка остаётся — без родителя в дереве.
- В режиме «плоского» списка фильтр работает так же: прячутся строки сессий.
- Полоса профилей живёт в общем футере сайдбара: над карточкой лимитов (если она
  включена) и над строкой настроек; при большом числе профилей чипы переносятся
  на вторую строку.
- Фильтр опирается на внутренние атрибуты официального браузера Workspaces.
  Если DSH поменяет разметку, фильтр просто перестанет прятать строки (список
  снова покажет всё) — данные при этом не пострадают.
